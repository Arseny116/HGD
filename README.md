# MiroIntegration

## О проекте

**MiroIntegration** — backend-приложение для создания Game Design Document (GDD), управления игровыми проектами и автоматической генерации PDF-документов.

Основная идея проекта — предоставить пользователю возможность создать полноценный GDD, заполнив семь тематических блоков, а затем получить готовый PDF-документ.

Генерация PDF выполняется асинхронно отдельным сервисом PdfWorker. Для взаимодействия между сервисами используется RabbitMQ, а для уведомления пользователя о завершении генерации — SignalR.

Проект разработан с использованием ASP.NET Core и построен с разделением ответственности между основным API и сервисом генерации документов.

## Запуск проекта

Для запуска проекта необходимо установить:

- Docker
- Docker Compose


### 1. Настройка окружения

Перед запуском необходимо настроить переменные окружения, используемые в Docker Compose.

В конфигурации должны быть указаны необходимые параметры:

- Подключение к PostgreSQL
- Подключение к RabbitMQ
- Настройки S3
- Параметры авторизации

Секреты и учетные данные не должны храниться непосредственно в репозитории.

### 3. Запуск приложения

```bash
docker compose up --build
```

Docker Compose запускает необходимые сервисы и инфраструктуру проекта.

Для остановки:

```bash
docker compose down
```

Для остановки с удалением контейнеров и сохранением данных в подключенных volumes:

```bash
docker compose down
```

## Архитектура проекта

Проект состоит из двух основных backend-сервисов.

### MiroIntegration

Основное ASP.NET Core Web API.

Отвечает за:

- Авторизацию пользователей
- Создание игровых проектов
- Управление семью блоками GDD
- Редактирование отдельных блоков
- Взаимодействие с PostgreSQL
- Создание задач генерации PDF
- Отправку сообщений в RabbitMQ
- Получение результатов генерации
- Сохранение статуса задач
- Отправку SignalR-уведомлений
- Предоставление защищенного API для скачивания PDF

### PdfWorker

Отдельный сервис, предназначенный для генерации PDF-документов.

Отвечает за:

- Получение задач из RabbitMQ
- Обработку данных проекта
- Генерацию PDF через QuestPDF
- Сохранение документов в S3
- Отправку события о завершении или ошибке генерации

PdfWorker не взаимодействует напрямую с frontend и не отвечает за пользовательскую авторизацию.

## Как работает проект

### 1. Создание GDD

Пользователь авторизуется и создает игровой проект.

Проект содержит семь основных блоков:

1. **Meta** — название игры, жанр, игровые элементы, количество игроков и обложка.
2. **Technical Specifications** — техническая форма игры, вид, платформы, языки и референсы.
3. **Gameplay** — описание игрового процесса, основные элементы и последовательность действий.
4. **Design Document** — дизайн-правила, рекомендации и определения.
5. **Flowchart** — схема игрового процесса, состоящая из узлов и связей.
6. **Player** — описание игрока, его характеристики, действия, оружие и награды.
7. **UI** — информация о пользовательском интерфейсе.

Все семь блоков объединяются в единый проект.

### 2. Редактирование проекта

После создания пользователь может редактировать отдельные блоки GDD.

Изменения сохраняются в PostgreSQL через основной API.

Проект представляет собой агрегат, объединяющий связанные данные игрового документа.

### 3. Запрос на генерацию PDF

Пользователь отправляет запрос на генерацию PDF.

MiroIntegration:

- Проверяет существование проекта
- Проверяет права доступа пользователя
- Создает задачу генерации документа
- Отправляет сообщение в RabbitMQ

После этого генерация выполняется асинхронно.

### 4. Обработка задачи PdfWorker

PdfWorker получает сообщение из RabbitMQ.

Далее сервис:

- Обрабатывает данные проекта
- Формирует PDF-документ
- Сохраняет документ в S3
- Отправляет результат обработки через RabbitMQ

Основной API не выполняет генерацию PDF самостоятельно.

### 5. Получение результата

MiroIntegration получает событие от PdfWorker.

После получения результата API:

- Обновляет статус задачи
- Сохраняет информацию о документе
- Обрабатывает результат генерации

Статус задачи хранится в PostgreSQL.

### 6. SignalR-уведомление

После завершения генерации MiroIntegration отправляет уведомление пользователю через SignalR.

Frontend получает информацию о завершении задачи и может предоставить пользователю возможность скачать документ.

SignalR используется для уведомлений, а не для передачи самого PDF-файла.

### 7. Скачивание PDF

Пользователь отправляет запрос на скачивание документа.

MiroIntegration проверяет права доступа и предоставляет файл из S3 через реализованный механизм скачивания.

Пользователь не должен иметь возможность получить PDF другого пользователя.

## Цель проекта

MiroIntegration разработан для практического изучения и применения backend-технологий .NET.

Основные задачи проекта:

- Разработка REST API
- Работа с реляционной базой данных
- Реализация асинхронной межсервисной коммуникации
- Разделение ответственности между сервисами
- Генерация документов
- Работа с объектным хранилищем
- Реализация авторизации и контроля доступа
- Контейнеризация и запуск приложения

Проект демонстрирует полный процесс создания игрового документа — от заполнения данных пользователем до генерации, хранения и скачивания готового PDF.
